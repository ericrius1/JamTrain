# Pose on WebRTC DataChannel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move per-frame hand pose data off the SpacetimeDB `hand_state` table onto the existing peer-to-peer WebRTC connection, and decouple "show partner as robot" from "is partner's hand pose fresh."

**Architecture:** SpacetimeDB keeps doing what it's good at — presence (the `player` table) and WebRTC signaling (offer/answer/ICE relay). High-rate pose data moves onto an `RTCDataChannel` already-negotiated by `WebRTCClient`. The remote rig's robot/human form is driven by partner *presence* (`partnerIdentity` from the player table), not by pose freshness. When a partner is present but pose data hasn't arrived yet (or has paused — e.g. their hands left the camera frame), the rig holds its last-known pose on the human form rather than morphing to robot.

**Tech Stack:** TypeScript, Three.js, SpacetimeDB (presence + signaling only after this), WebRTC (`RTCPeerConnection` + `RTCDataChannel`), Vite.

**Verification model:** This project has no unit-test framework wired up. Each task includes a manual verification step using two browser windows (or two profiles) on `npm run dev`, where you can observe partner presence/pose in real time. Where a step needs runtime introspection, use `console.info` lines that already exist (`[webrtc] …`, `[jam-train] …`) plus any new ones the task introduces.

## File Structure

**Modified:**
- `src/game/webrtc.ts` — gains a pose `RTCDataChannel`, `sendPose()`, and `onRemotePose()` listener API. Owns the channel lifecycle (offerer creates pre-offer; answerer wires `pc.ondatachannel`). Negotiation, ICE, and media-track plumbing stay as-is.
- `src/game/multiplayer.ts` — pose API stays (`sendPose`, `getRemotePose`), but the body delegates to `WebRTCClient` for transport and exposes a setter (`applyRemotePose`) so `Game` can route inbound DataChannel pose into the same `remotePose` field. `acceptHandState`, the `handState` callbacks, and the `update_pose` reducer call are removed. `getRemotePose()` no longer gates on `POSE_STALE_MS` (the partner-identity listener is now the presence source of truth).
- `src/game/Game.ts:670–680` (the `update()` rig-driving block) — `robotTarget` is driven by `partnerPresent` (a flag updated from `multiplayer.onPartnerIdentity`), not by pose freshness. Wires `webrtc.onRemotePose → multiplayer.applyRemotePose`.
- `spacetimedb/src/index.ts` — `hand_state` table + `update_pose` reducer deleted. `leave_room` and `on_disconnect` no longer reference `handState`.
- `src/module_bindings/*` — regenerated by `npm run spacetime:generate` after the server change. Stale `hand_state_table.ts`, `update_pose_reducer.ts`, etc. are removed by the regeneration.

**No new files** — every change fits in existing modules.

```ts
private wirePoseChannel(channel: RTCDataChannel): void {
  this.poseChannel = channel;
  channel.onopen = () => console.info('[webrtc] pose channel open');
  channel.onclose = () => console.info('[webrtc] pose channel closed');
  channel.onerror = err => console.warn('[webrtc] pose channel error', err);
  channel.onmessage = event => {
    const data = event.data;
    if (typeof data !== 'string') return;
    for (const listener of this.poseListeners) listener(data);
  };
}
```
